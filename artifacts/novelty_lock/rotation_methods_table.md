# Rotation Method Differentiation Table

This table locks the novelty boundary for the rotation-first sprint. ParoQuant,
QuaRot, SpinQuant, MambaQuant, and Rotated Runtime Smooth are prior methods or
baselines. DriftRot candidates are only paper-worthy if they use long-decode
signals to select a surface, branch, correction set, or confirmed tail-safe
configuration beyond static ParoQuant.

| Method | method_type | static_vs_decode_adaptive | calibration_target | uses_long_decode_drift? | uses residual correction? | uses surface/branch selection? | kernel/runtime implication | safe claim for our paper | unsafe claim to avoid |
|---|---|---|---|---|---|---|---|---|---|
| ParoQuant | Pairwise rotation + channel scaling W4A16 baseline | Static calibration-time transform | Weight/activation conditioning for reasoning inference | No direct decode-drift selection in our usage | No | No | Folded weight transform; no dynamic mask kernel in our reproduction | Strong rotation baseline that outperforms channel-set protection on Granite, Nemotron, Falcon, and DeepSeek in our packets | Calling ParoQuant our method; implying our clip retune is a new quantizer without held-out drift/tail gain |
| QuaRot | Computationally invariant rotations for quantized LLM inference | Static rotations | Residual/FFN/attention/KV-cache surfaces | No | No | Rotation folding plus Hadamard-style transforms depending surface | Prior rotation family showing basis changes can improve low-bit inference | Claiming first rotation-based quantization or first surface-aware rotation broadly |
| SpinQuant | Learned rotation optimization for quantization | Static learned transform | Quantized network accuracy | No | No | Requires learned rotations/optimization; folded or runtime transforms | Prior learned-rotation baseline pressure; motivates avoiding broad rotation novelty claims | Claiming learned or optimized rotation novelty unless we actually train/confirm drift-specific rotations |
| MambaQuant | Mamba/SSM-oriented PTQ with KLT/smoothing/rotation-style components | Static calibration-time PTQ | Mamba/SSM activation outliers and quantization robustness | No long-decode drift protocol in our contribution boundary | No | SSM-specific surfaces, but not our block-output drift protocol | Mamba-specific PTQ kernels/transforms | Prior for SSM-specific quantization; our safe claim must be measured long-decode surface stability, not generic SSM rotation | Saying Quamba/Mamba prior is wrong without internal-surface measurements |
| Rotated Runtime Smooth | Rotation plus runtime activation smoothing | Runtime-adjacent, but not selected by our long-decode drift map | Activation smoothing/rotation for low-bit inference | No in our sense unless it measures decode-position drift | No | Not branch/surface selected by our protocol | Runtime activation smoothing overhead | Adjacent prior showing rotation plus runtime adjustment exists | Claiming runtime rotation/smoothing as novel in itself |
| DriftRot CVaR/Clip | Tail-aware configuration screen over ParoQuant-style clip ranges | Static config selected with calibration/confirmation split | Worst-trace/CVaR recovery under long-decode traces | Yes, only through tail/drift packet selection | No | No | Same ParoQuant-style inference cost if config is static | Tier-2 screen: drift/tail-aware ParoQuant configuration selection if confirmation improves CI/tail | Headlining as a new method; presenting hyperparameter tuning as DriftRot without held-out gain |
| DriftRot residual correction | Post-rotation protected-column residual correction | Decode-conditioned selection can be static or dynamic depending final design | Post-rotation residual error under long-decode traces | Yes, P selected from long-decode residual/error signal | Yes: `y = x W_pq + x_P (W_fp - W_pq)_P` | Optional, if P is surface-specific | Adds protected-column correction working set; must report HBM bytes/token, working-set size, and pJ/token estimate | Tier-1 candidate: long-decode selected residual correction in rotated basis, evaluated against ParoQuant | Generic rotation plus correction claim; original-basis magnitude protection claim |
| DriftRot surface-selected rotation/protection | Surface-selection protocol plus optional rotation/protection | Decode-adaptive selection of where to intervene; transform may be static after selection | Internal surfaces with lower drift than block outputs | Yes | Maybe, if combined with residual correction | Yes | Requires hooks or surface-specific kernels; surface must show lower drift first | Tier-1 candidate: surface-distinction protocol for long-decode W4A16 drift | Claiming Quamba2 is wrong unless internal surfaces are measured |
| DriftRot BranchRot | Branch-local rotation/protection for parallel hybrid models | Branch-selected; transform may be static per branch | Falcon parallel branch surfaces | Yes | Optional | Yes, branch-local | Branch-local hooks/transforms; only justified if branch drift/range is lower than post-mixer | Tier-1 candidate if Falcon branch-local diagnostics beat post-mixer and improve recovery | Generic architecture-aware rotation without branch-local evidence |
| DriftRot rotation refresh | Decode-window rotation refresh or selected refresh schedule | Decode-adaptive | Early-vs-late covariance/range drift | Yes | No | Maybe; refresh may require runtime transform overhead | Tier-1 if early/late covariance drift is material and held-out refresh improves ParoQuant | Static ParoQuant retune labeled as adaptive refresh |
